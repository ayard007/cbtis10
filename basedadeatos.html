PRESENTACIÓN

Introducción

Cada vez que la escuela consulta tu boleta, que una tienda revisa si hay existencia de un producto o que una aplicación recuerda tu usuario, hay una base de datos trabajando detrás. La información no está guardada al azar: está diseñada, organizada en estructuras que permiten guardarla, buscarla y actualizarla sin errores.

En esta guía no memorizarás definiciones sueltas. Vas a construir tu comprensión resolviendo un problema real, poniendo a prueba tus decisiones en siete juegos interactivos y, al final, diseñando la base de datos de un caso de tu propio entorno. Todo lo que aprendas aquí es directamente aplicable a tus clases de bachillerato y a tu formación técnica.

Al terminar serás capaz de
  • Distinguir entre dato e información y explicar para qué sirve un SMBD ofimático.
  • Identificar los componentes de una tabla: campos, registros, celdas y claves.
  • Elegir el tipo de dato y la clave primaria adecuados para cada campo.
  • Reconocer los tipos de relación (1:1, 1:N, N:M) y aplicar el proceso de diseño.
Metodología de trabajo

Esta guía sigue una pedagogía activa, un enfoque constructivista y el aprendizaje basado en problemas (ABP): partirás de un problema concreto, formularás hipótesis, las verificarás con los juegos y llegarás a conclusiones que tú mismo construirás. El conocimiento no se recibe: se elabora.

Tres meses después el desorden es total: hay libros anotados dos veces, nombres escritos de distintas formas para la misma persona, préstamos sin fecha de devolución y nadie sabe qué libros faltan.

CONCEPTO CENTRAL

¿Qué es una base de datos?

Una base de datos es un conjunto de información organizada de forma estructurada para que sea fácil de almacenar, buscar y actualizar. La palabra clave es organizada: no es cualquier montón de información, sino información ordenada según reglas.

Para entenderla, primero hay que separar dos ideas que suelen confundirse:

Dato
Un hecho aislado, sin contexto. Por sí solo no dice mucho. Ejemplo: 18, "Ana", 2026-05-14.
Información
Datos procesados y relacionados que adquieren significado y sirven para decidir. Ejemplo: "Ana, de 18 años, devolvió el libro el 14 de mayo de 2026".

Una base de datos guarda datos; al relacionarlos y consultarlos, obtenemos información. Comprueba si ya distingues uno de otro:

HERRAMIENTA

Sistemas manejadores de bases de datos (SMBD)

Un sistema manejador de bases de datos ofimáticas (SMBD) es el programa que nos permite crear, guardar, consultar y modificar una base de datos sin programar desde cero. En el ámbito ofimático los más comunes son:

Microsoft Access
Parte del paquete Office. Permite crear tablas, formularios, consultas e informes con un entorno visual.
LibreOffice Base
Alternativa gratuita y de código abierto, con funciones equivalentes a las de Access.

Ambos trabajan con el modelo relacional: la información se guarda en tablas que pueden conectarse entre sí. Este es el modelo que usarás en tus clases y el que estudiaremos aquí.

Ofimática, en contexto

"Ofimática" viene de oficina + informática: son las herramientas digitales para el trabajo de oficina. Un SMBD ofimático está pensado para que una persona, sin ser programadora, gestione la información de una escuela, un negocio o un proyecto.

ESTRUCTURA

Componentes de una tabla

La tabla es la pieza fundamental de una base de datos relacional. Se parece a una cuadrícula, pero cada parte tiene un nombre técnico:

Tabla
Conjunto de datos sobre un mismo tema (por ejemplo, ALUMNOS).
Campo (columna)
Cada característica que se guarda: nombre, grupo, correo. Todos los registros comparten los mismos campos.
Registro (fila)
Toda la información de un solo elemento: un alumno completo.
Celda / dato
El cruce de un campo con un registro: un valor concreto.

id_alumnonombregrupocorreo
1Ana Torres3-Aana@correo.mx
2Luis Mena3-Aluis@correo.mx
3Sara Ruiz3-Bsara@correo.mx

DEFINICIÓN DE CAMPOS

Tipos de datos

Al diseñar cada campo debemos indicar qué tipo de dato almacenará. Esto obliga al sistema a aceptar solo valores válidos: si un campo es de tipo Fecha, no permitirá escribir "casa". Los tipos más usados en un SMBD ofimático son:

Texto corto
Palabras y frases: nombres, direcciones. También datos como teléfonos que no se operan matemáticamente.
Número
Cantidades con las que se puede calcular: edad, cantidad en existencia.
Fecha / Hora
Fechas y horas: fecha de nacimiento, fecha de préstamo.
Sí / No (booleano)
Valores de dos estados: ¿pagado?, ¿activo?, ¿entregado?
Moneda
Valores monetarios con formato de dinero: precio, total.
Autonumérico
Número que el sistema asigna solo, sin repetirse. Ideal para claves primarias.
Regla práctica

Un número de teléfono se guarda como Texto, no como Número: nunca lo sumamos ni restamos, y puede empezar con cero. Elige el tipo por el uso del dato, no solo por su apariencia.

IDENTIDAD Y CONEXIÓN

Claves: primaria y foránea

Para que no existan registros duplicados ni confusiones, cada tabla necesita una forma de identificar sin ambigüedad a cada elemento. Ahí entran las claves.

Clave primaria (PK)
Campo que identifica de forma única a cada registro. No se repite y no puede quedar vacío. Ejemplo: id_alumno.
Clave foránea (FK)
Campo que conecta una tabla con la clave primaria de otra. Así se relacionan las tablas. Ejemplo: id_alumno dentro de PRESTAMOS.

Una buena clave primaria es única, estable y nunca cambia. Por eso el nombre no sirve (dos personas pueden llamarse igual) y suele usarse un campo Autonumérico. Practica eligiendo la mejor:

MODELO RELACIONAL

Relaciones entre tablas

La gran ventaja del modelo relacional es dividir la información en varias tablas y conectarlas, evitando repetir datos. Existen tres tipos de relación según cuántos registros de una tabla se asocian con cuántos de la otra:

Uno a uno (1:1)
Un registro se asocia con un único registro de la otra tabla. Ej.: un alumno tiene una sola credencial.
Uno a muchos (1:N)
Un registro se asocia con varios de la otra tabla. Ej.: un grupo tiene muchos alumnos. Es la más común.
Muchos a muchos (N:M)
Varios registros de una tabla se asocian con varios de la otra. Ej.: los alumnos cursan varias materias y cada materia tiene varios alumnos.

METODOLOGÍA

Proceso de diseño de una base de datos

Diseñar una base de datos no es empezar a escribir tablas al azar: es seguir un orden que va del problema a la estructura. Estos son los seis pasos que aplicarás en tu actividad práctica:

  1. Identificar el propósito y los requisitos. ¿Qué información se necesita guardar y para qué? Aquí regresas al problema.
  2. Identificar las entidades (tablas). Cada "cosa" o "tema" sobre el que guardas datos se convierte en una tabla: ALUMNOS, LIBROS, PRESTAMOS.
  3. Definir los campos y sus tipos de datos. Qué características guardas de cada entidad y de qué tipo son.
  4. Establecer la clave primaria de cada tabla. El campo que identifica sin ambigüedad a cada registro.
  5. Definir las relaciones entre tablas. Conectas las tablas con claves foráneas y determinas si son 1:1, 1:N o N:M.
  6. Aplicar normalización y revisar. Eliminas datos repetidos y verificas que el diseño responda al problema original.

    CALIDAD DEL DISEÑO

    Normalización básica

    La normalización es el proceso de organizar los datos para evitar repeticiones e inconsistencias. Su idea básica en este nivel es sencilla: cada dato debe guardarse una sola vez, en el lugar que le corresponde.

    Observa el problema. Esta tabla mezcla información de préstamos y de alumnos, repitiendo el nombre y el grupo cada vez:

    Diseño NO normalizado (con repeticiones)
    librofechaalumnogrupo
    Física I2026-05-02Ana Torres3-A
    Química2026-05-04Ana Torres3-A
    Historia2026-05-05Ana Torres3-A

    Si Ana cambia de grupo, habría que corregir varias filas y es fácil olvidar alguna. La solución: separar en dos tablas conectadas por una clave. El nombre y el grupo de Ana se guardan una sola vez en ALUMNOS; PRESTAMOS solo referencia su id_alumno.

    Señales de que falta normalizar
    • El mismo dato aparece escrito muchas veces.
    • Al cambiar un dato hay que corregirlo en varios lugares.
    • Una misma columna mezcla temas distintos (datos del libro y del alumno juntos).

    En tu vida diaria interactúas con decenas de bases de datos sin darte cuenta: cuando la escuela consulta tu boleta, cuando una tienda revisa su inventario o cuando una clínica busca un expediente. ¿Qué pasaría en tu escuela, tu comunidad o tu familia si toda esa información dejara de estar organizada en bases de datos y volviera a guardarse en hojas de papel sueltas?     Instrucciones paso a paso

    1. Reflexiona antes de escribir. Piensa en un caso real y cercano; no un ejemplo genérico de internet.
    2. Redacta tu aporte inicial (mínimo 5 renglones) respondiendo la pregunta: dos consecuencias + tu situación real.

    Se evalúa: claridad del argumento, uso de los conceptos de la unidad, calidad de las respuestas a tus compañeros.
